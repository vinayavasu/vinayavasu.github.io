RAG Red Teaming: Extracting PII via Prompt Injection

LLM01 · Prompt Injection LLM02 · Sensitive Info Disclosure MITRE ATLAS RAG Security

Problem

A RAG-based AI assistant was exposed to potential prompt injection and data leakage risks. Could an attacker extract PII by manipulating retrieval context or user prompts?

Approach

  • Built a RAG pipeline with a document store, retrieval layer, and LLM
  • Designed prompt injection attacks targeting user prompts and retrieval context
  • Tested jailbreak patterns, indirect prompt injection, and context-collision attacks
  • Mapped findings to OWASP LLM Top 10 (LLM01, LLM02)

What broke

  • Successfully extracted PII and internal documents via prompt injection
  • Demonstrated context manipulation forcing the LLM to return confidential data

Guardrails built

  • Evaluated LLM Guard for prompt sanitization and output filtering
  • Designed input validation and output handling patterns to reduce injection risk
  • Created AI threat models using IriusRisk to document attack surfaces
  • Integrated AI security checks into CI/CD pipeline for early detection
Impact: Established a concrete, reproducible RAG attack pattern. Provided a practical reference for teams building RAG products. All findings mapped to OWASP LLM Top 10 and MITRE ATLAS.

Adversarial ML: Flipping Sentiment Classifiers with Single-Word Substitutions

Adversarial ML MITRE ATLAS · AML.T0015 TextAttack

Problem

A sentiment classifier in production was vulnerable to adversarial inputs that could flip predictions while preserving semantic meaning, bypassing human review.

Approach

  • Used TextAttack to generate adversarial examples against a sentiment model
  • Tested single-word substitutions, paraphrasing, and character-level perturbations
  • Measured prediction confidence deltas and semantic similarity scores

What broke

  • Single-word input changes flipped model predictions with 99%+ confidence
  • Adversarial inputs remained semantically consistent while being completely misclassified

Guardrails built

  • Applied adversarial training and robustness checks to the model
  • Designed input validation and anomaly detection for suspicious patterns
  • Mapped attack techniques to MITRE ATLAS adversarial ML framework
Impact: Proved that minimal input changes can cause high-confidence misclassifications. Concrete adversarial ML risk demonstration for AI product teams.

Embedding AI Security Checks into CI/CD Pipelines

DevSecOps Supply Chain LLM08 · Model Integrity Cosign

Problem

AI-powered features were being shipped without LLM-specific security checks. Traditional pipeline scanning missed prompt injection patterns and model integrity risks.

What I built

  • Added checks for prompt injection patterns in templates and configs
  • Model scanning and signing with Cosign for supply-chain integrity
  • Automated triage workflows in Python and Bash to reduce manual overhead

Pipeline stages

  • Scan prompts and templates for injection patterns at commit time
  • Validate model signatures before deployment

Impact: Early detection of AI-specific risks before production. Reduced manual security overhead and improved fix rates across the delivery pipeline.

TextAttack Adversarial ML: Attacking a Sentiment Classifier
Built a DistilBERT-based sentiment classifier, then used TextAttack's TextFooler recipe to generate adversarial examples. Single-word substitutions flipped model predictions with 99%+ confidence while preserving semantic meaning. Mapped to MITRE ATLAS AML.T0043.
Adversarial ML MITRE ATLAS · AML.T0043 TextAttack DistilBERT TextFooler
MODEL
distilbert-base-uncased-finetuned-sst-2-english · fine-tuned on SST-2 dataset · CPU/GPU via PyTorch
ATTACK RECIPE
TextFoolerJin2019 — synonym substitution preserving semantic similarity · 20 examples · results logged to CSV
WHAT I BUILT
Custom SentimentWrapper class bridging HuggingFace inference with TextAttack's attack loop · per-example word-change metrics · attack_summary.txt output
STACK
Python · PyTorch · HuggingFace Transformers · TextAttack 0.3.10 · NLTK · scikit-learn
BEST ATTACK — EXAMPLE 12
ORIGINAL
"I think this product is nice and works well for my needs."
POSITIVE · 99.66% confidence
ADVERSARIAL
"I think this product is nice and works better for my needs."
NEGATIVE · 99.79% confidence
"well" → "better" is semantically more positive in plain English — yet the model flipped with higher confidence. "better" may signal implicit comparison, implying something else was worse. Training bias at work. This is the attack surface.
  • Demonstrated that single-word synonym substitutions flip high-confidence predictions — model is vulnerable to semantically-preserving perturbations that bypass WAF and regex entirely
  • Built custom ModelWrapper class converting HuggingFace softmax outputs to the [negative_prob, positive_prob] tensor format TextAttack expects
  • Ran 20-example attack dataset with TextFoolerJin2019; collected word modification rate per example and overall success rate
  • Mapped attack to MITRE ATLAS AML.T0043 (Craft Adversarial Data) and OWASP LLM09 (Misinformation)
  • Defense takeaways: adversarial training, input normalization before tokenization, ensemble-based anomaly detection — signature-based tools are blind to this class of attack

The Diana Initiative 2026 · 31 Slides · May 30, 2026

Before You Hack It, Understand It:
AI Security Fundamentals

🌐 Online  ·  🕐 Pacific Daylight Time  ·  ⏱ 26 minutes

Security practitioners are increasingly handed AI targets to audit — yet many still treat the model as a black box. This talk opens that box: eight processing layers between user input and model output, each one mapped to its attack surface. From tokenization tricks that bypass WAFs to temperature abuse at inference time — with every attack mapped to OWASP LLM Top 10 and MITRE ATLAS.

Prompt Injection Data Poisoning Adversarial ML Supply Chain MITRE ATLAS OWASP LLM Top 10 RAG Security LLM Architecture
01 · ARCHITECTURE
The Neural Building Blocks
8-step pipeline — tokenization → embeddings → context assembly → attention → decoder output. Every layer mapped to its attack surface.
02 · EXPLOITATION
Where Real Attacks Live
Evil twin, data poisoning, supply chain, adversarial inputs, temperature abuse — each attack pinned to the exact layer it targets.
03 · THREAT MODELING
The AI Attack Surface Map
One consolidated table: attack type → pipeline layer → OWASP ID → MITRE TTP → key mitigation. Screenshot and use Monday morning.
04 · ACTION PLAN
5 Questions to Ask
Data provenance, model integrity, input sanitization, inference params, system prompt storage — the audit checklist for any AI system.
CORE THESIS
"AI security is about hardening a probabilistic pipeline — not protecting a smart brain. Stop treating LLMs as black-box magic. Treat them as untrusted execution environments."
